## 배경 / 목적

지금 레벨은 **온보딩에서 한 번 정해지면 영원히 그대로**다(클라이언트가 운전 경험 점수로 계산해 전송, 스펙 004). 사용자가 연습을 아무리 많이 해도 Seed는 계속 Seed다.

이번에 **누적 주행거리로 레벨이 오르게** 한다. 연습 코스를 다녀오면(스펙 011의 방문 기록) 그때 측정된 인정 주행거리가 쌓이고, 기준에 도달하면 레벨이 즉시 오른다. 마이페이지에는 **다음 레벨까지 얼마나 남았는지 게이지**로 보여준다.

이 변경으로 **레벨의 주인이 바뀐다**: 온보딩 시점의 최초 배정은 여전히 클라이언트가 계산해 보내지만(스펙 004), **그 이후 승급은 서버가** 누적 거리로 판단한다.

### 범위 밖

- **뱃지·리워드** — Navigator 도달 이후의 보상 체계(정책 미정, 게이지는 100% 고정).
- **거리 차감·보정** — 연습기록을 지워도 누적 거리·레벨은 유지된다(되돌리는 경로 없음).
- **레벨 하향** — 어떤 경우에도 레벨은 내려가지 않는다.
- **중복 방문 호출 가드** — 아래 "확정된 결정" 참고(의도적으로 두지 않음).

## 요구사항

### 기능 요구사항

1. **누적 주행거리 보관**: 회원마다 누적 주행거리를 저장한다.
2. **온보딩 초기값**: 온보딩으로 Rookie 이상이 부여되면 누적 거리를 **그 레벨의 최소 기준값**으로 초기화한다(Seed는 0).
3. **거리 반영**: 방문을 기록하는 시점(스펙 011의 `POST /practices/{id}/visits`)에 **인정 주행거리**(앱이 GPS로 측정해 보낸 값)를 누적한다.
   - **코스만 반영**한다. 주차장은 인증 대상이 아니라 0.
   - 같은 코스를 여러 번 다녀오면 **방문마다 각각** 반영한다(같은 날이어도 동일).
   - **측정 없이 "다녀왔어요"만 누른 경우 거리는 0**이다(경로만 보기·알림 거부).
   - **한 방문에 누적되는 거리는 그 코스의 전체 거리를 넘지 않는다** — `min(앱이 보낸 값, course.distance_meters)`.
   - 후기 작성 여부와 무관하다.
4. **레벨 승급**: 누적 거리가 다음 레벨 기준에 도달하면 **즉시** 레벨을 올린다. 한 번의 반영으로 **두 단계 이상** 오를 수도 있다(긴 코스).
   - 승급해도 **이전에 쓴 후기의 작성 당시 레벨은 그대로**다(스펙 010) — 그래서 이전 레벨 후기는 수정 불가·삭제 가능이라는 기존 규칙이 그대로 적용된다.
5. **레벨업 알림**: 방문 처리 응답에 **레벨업 여부와 새 레벨**을 실어 보내 클라이언트가 팝업을 띄운다.
6. **마이페이지 게이지**: 현재 레벨·누적 거리·현재 레벨 시작 거리·다음 레벨 기준 거리·진행률을 반환한다. Navigator는 진행률 100% 고정.

### 비기능 요구사항

- 거리는 **미터(정수)로 저장**하고 **응답은 km(소수 첫째 자리)** 로 준다 — 코스 주행거리(`course.distance_meters`)가 미터 단위라 변환 손실을 저장에 남기지 않는다.
- 승급 판정은 방문 처리 트랜잭션 안에서 함께 처리한다(거리만 쌓이고 레벨이 안 오르는 상태가 없도록).
- **누적 갱신은 잃어버리는 일이 없어야 한다.** 읽고-더하고-쓰기 사이에 다른 방문이 끼면 한쪽이 사라진다(lost update). 회원 행을 잠그거나 원자적 UPDATE로 처리한다.
- 응답 km는 **소수 첫째 자리에서 내림**한다(진행률과 같은 방향 — 실제보다 앞서 보이지 않게).

## 누적 거리 상한

레벨은 **내려가지 않는다.** 한 번 잘못 오르면 되돌릴 방법이 없으므로, 앱이 보낸 값을 그대로 쌓지 않는다.

**한 방문에 누적되는 거리 = `min(앱이 보낸 인정 주행거리, 코스 전체 거리)`**

| 코스 | 앱이 보낸 값 | 누적 | 
|------|--------------|------|
| 5km | 2.1km | 2.1km |
| 5km | 6km | **5km** (왕복·이탈 후 복귀로 더 나올 수 있으나 코스 값어치까지만) |
| 5km | 600km | **5km** (버그·조작 차단) |
| 주차장(거리 없음) | 3km | **0** |

- **인증 판정과는 별개다.** 인증은 `min(코스거리 × 40%, 5km)`라는 *하한*(이만큼 달렸으면 다녀온 것으로 친다)이고, 이건 *상한*(아무리 보내도 이만큼까지만 쌓는다)이다. 둘은 서로 간섭하지 않는다.
- 코스 전체 거리를 기준으로 삼은 이유는 **서버가 이미 아는 값**이라 새 정책 상수가 필요 없고, 코스 길이에 비례해 자연스럽게 걸리기 때문이다. 고정 상한(예: 50km)은 짧은 코스에서 방어가 헐거워진다.
- 부작용: 한 번에 두 바퀴 돈 사람은 한 바퀴만 인정된다. 방문을 두 번 기록하면 두 번 누적되므로 실질 손해는 크지 않다.
- **중복 호출 가드가 없으므로 이 상한이 유일한 서버 측 방어선**이다(아래 "확정된 결정" 참고).

## 레벨 기준

| 레벨 | 시작 거리 | 다음 목표 |
|------|-----------|-----------|
| `SEED` | 0 km | 50 km |
| `ROOKIE` | 50 km | 150 km |
| `OWNER` | 150 km | 300 km |
| `EXPLORER` | 300 km | 600 km |
| `NAVIGATOR` | 600 km | — (최상위) |

저장은 미터라 각각 `0` / `50_000` / `150_000` / `300_000` / `600_000`이다.

**진행률** = `(누적 - 현재 레벨 시작) / (다음 목표 - 현재 레벨 시작) × 100`, 0~100 정수(내림). Navigator는 계산 없이 **100**.

예) Rookie가 100km면 `(100-50)/(150-50) = 50%`.

## 도메인 모델 (마이그레이션 V21)

### member 확장

| 필드 | 타입 | NN | 설명 |
|------|------|----|------|
| total_distance_meters | bigint | Y (default 0) | 누적 주행거리(미터). 차감되지 않는다 |

- **기존 회원 백필**: 온보딩을 마친 회원은 현재 레벨의 최소 기준값으로 채운다(Rookie 50km → 50000 …). Seed·미온보딩은 0.
- 레벨 임계값은 `Level` enum에 붙이거나 별도 정책 클래스(`LevelPolicy`)에 둔다 — 화면·서버가 같은 표를 봐야 하므로 **서버가 단일 출처**다.
- 승급 로직은 엔티티에 둔다: `Member.addDistance(int meters)` → 누적 후 도달한 레벨로 올리고 **승급 여부를 반환**(호출부가 응답에 실어 보냄).

## API 명세

기존 두 API의 **응답만 확장**한다. 새 엔드포인트는 없다.

### 1. 마이페이지 조회 (스펙 006 확장)

```json
// GET /api/v1/members/me   (JWT)
// Response data
{
  "nickname": "차근차근 토끼",
  "level": "ROOKIE",
  "recommendationTags": ["U_TURN", "INTERSECTION", "PARKING"],
  "drivingGoal": "골목길에 익숙해지기",
  "savedPlaceCount": 12,
  "levelProgress": {
    "totalDistanceKm": 100.0,
    "currentLevelStartKm": 50.0,
    "nextLevelKm": 150.0,
    "progressPercent": 50
  }
}
```

- `level`은 기존 최상위 필드를 그대로 쓴다(중복 방지).
- **Navigator**: `nextLevelKm`은 `null`, `progressPercent`는 `100`.

```json
"levelProgress": {
  "totalDistanceKm": 812.4, "currentLevelStartKm": 600.0,
  "nextLevelKm": null, "progressPercent": 100
}
```

### 2. 방문 기록 (스펙 011 확장)

방문 기록 응답(인증 결과)에 **레벨 진행 결과를 덧붙인다** — 레벨업 팝업을 위해서다.

```json
// POST /api/v1/practices/12/visits   (JWT)
// Request — 상태는 보내지 않는다. 이 호출 자체가 "다녀왔어요"다.
{ "certifiedDistanceMeters": 5200 }

// Response data — 아래 세 필드가 이 스펙에서 더해진다
{
  "visitCount": 3,
  "addedCertifiedDistanceMeters": 5200,
  "requiredDistanceMeters": 2000,
  "isCertifiedNow": true,
  "isVerified": true,

  "totalDistanceKm": 152.3,
  "levelUp": true,
  "newLevel": "OWNER"
}
```

- 누적되는 값은 **인정 주행거리**(`addedCertifiedDistanceMeters`)다. 측정 없이 다녀왔어요만 누르거나 주차장이면 0이라 누적도 승급도 없다.
- **미방문 사유 제출**(`POST /practices/{id}/skip-reason`)은 거리에 영향이 없다 — 응답도 지금처럼 비어 있다.
- 두 단계 이상 오르면 `newLevel`은 **최종 도달 레벨**이다.

## 완료 조건 (Acceptance Criteria)

- [x] 온보딩으로 Rookie가 부여되면 누적 거리가 50km로 초기화된다(Owner 150 / Explorer 300 / Navigator 600, Seed 0).
- [x] 기존 회원 백필 후 각자 레벨의 최소 기준값을 갖는다.
- [x] 코스 방문을 기록하면 **인정 주행거리**가 누적되고, 같은 코스를 다시 다녀오면 **또 누적**된다.
- [x] 측정값 없이(거리 생략) 방문을 기록하면 누적 거리는 변하지 않는다.
- [x] 코스 전체 거리보다 큰 값을 보내도 **코스 거리까지만** 누적된다(600km를 보내도 5km 코스는 5km).
- [x] 같은 회원의 방문 기록이 동시에 처리돼도 누적 거리가 유실되지 않는다.
- [x] 주차장 방문은 누적 거리를 바꾸지 않는다.
- [x] 미방문 사유 제출은 거리에 영향이 없다.
- [x] 직전 방문 후 10분 안의 재호출은 횟수·거리·레벨을 바꾸지 않고 현재 상태를 200으로 돌려준다.
- [x] 누적이 다음 기준에 도달하면 레벨이 즉시 오르고, 응답의 `levelUp`·`newLevel`로 알 수 있다.
- [x] 한 번의 반영으로 두 단계 이상 오르는 경우 `newLevel`이 최종 레벨이다.
- [x] 연습 항목을 삭제해도 누적 거리·레벨은 그대로다.
- [x] 마이페이지 `levelProgress`의 진행률이 구간 비율과 일치한다(Rookie 100km → 50).
- [x] Navigator는 `nextLevelKm=null`·`progressPercent=100`이고, 그 뒤로도 누적 거리는 계속 쌓인다.
- [x] 레벨이 오른 뒤 이전 레벨에서 쓴 후기는 수정 불가(409)·삭제 가능이 유지된다.
- [x] 관련 테스트 통과 (`./gradlew test`).

## 확정된 결정 (리뷰 반영)

- **코스만 거리 반영**(주차장 0).
- **레벨업 알림은 방문 처리 응답에** 실어 보낸다(클라이언트가 팝업).
- **Navigator 이후에도 누적은 계속** 쌓되 게이지는 100% 고정.
- **기존 회원은 백필**로 레벨 최소값을 채운다.
- 응답 단위는 **km**(소수 첫째 자리 내림), 저장은 미터.
- **한 방문의 누적 상한은 코스 전체 거리.** 레벨이 내려가지 않는 이상 조작·오차를 되돌릴 수 없어, 서버가 아는 값으로 잘라낸다.
- **중복 호출 가드로 쿨다운을 둔다**([ADR 0012](../adr/0012-visit-record-duplicate-guard.md)). 직전 방문 후 10분 안의 같은 항목 호출은 같은 방문으로 보고 무시하며, 앱이 재시도하지 않도록 200과 현재 상태를 돌려준다. 누적 상한이 한 번의 피해를 묶고 쿨다운이 호출 횟수를 줄여 함께 작동한다. 정확한 중복 제거(멱등키)는 클라이언트 변경이 필요해 미룬다 — 짧은 코스를 10분 안에 두 바퀴 돌면 두 번째가 버려지고, 완전 동시 요청은 막지 못한다.
