## 배경 / 목적

장소 검색(스펙 007)을 쓰는 로그인 회원이 이전에 검색한 키워드를 다시 빠르게 찾도록 **최근 검색어**를 서버에 보관한다. 검색창 진입 시 목록으로 보여주고, 개별·전체 삭제를 지원한다. **로그인 유저 전용**(비로그인은 저장·조회 안 함).

**범위 밖**: 검색어 자동완성, 인기 검색어, 검색어 기반 추천.

## 요구사항

### 기능 요구사항

1. **자동 저장**: 로그인 회원이 검색(`GET /places/search`)하면 서버가 키워드를 자동 기록한다(클라 별도 호출 없음). 첫 페이지(cursor 없음)에서만 기록해 페이지네이션 재조회로 중복 기록되지 않게 한다.
   - **중복 제거**: 같은 키워드를 다시 검색하면 새 행을 추가하지 않고 **최신으로 갱신**(맨 앞으로 이동).
   - **보관 개수 상한**: **15개**. 초과 시 **가장 오래된 것부터 제거**.
2. **조회**: 회원의 최근 검색어를 **최신순**으로 반환(상한 개수 이내).
3. **삭제**: 검색어 **개별 삭제**(id 지정)와 **전체 삭제**를 지원한다.

### 비기능 요구사항

- 전부 **JWT 필수**(비로그인 사용 불가).
- 자동 저장은 검색 조회(readOnly)와 **분리된 별도 트랜잭션 write**로 처리한다. 지금은 **동기**(검색 응답 전 기록) — upsert 한 방이라 지연이 미미해 최적화 없이 시작한다. 검색 응답에서 완전히 떼어내는 최적화(커밋 후 이벤트·비동기)는 후속(범위 밖).

## 도메인 모델 (마이그레이션 V10)

**member_recent_search** (회원 ↔ 검색어, 1:N)
| 필드 | 타입 | 설명 |
|------|------|------|
| id | bigint PK | |
| member_id | bigint FK→member | |
| keyword | varchar(50) | 검색 키워드(트림 후, 스펙 007과 동일 1~50자) |
| searched_at | timestamptz | 마지막 검색 시각(중복 갱신 시 갱신) |

- **unique(member_id, keyword)** — 회원 내 키워드 유일. 재검색은 `INSERT ... ON CONFLICT (member_id, keyword) DO UPDATE SET searched_at = now()`로 갱신(중복 없이 맨 앞으로).
- 조회 정렬: `searched_at DESC, id DESC`.
- 상한 유지: 저장 후 상한(15) 초과분을 `searched_at` 오래된 순으로 삭제.
- `member` 삭제(하드 삭제 시) 대비 FK는 `ON DELETE CASCADE`. (soft delete가 기본이라 실제 삭제는 익명화 배치에서만.)

## API 명세 (패키지 `domain.member`)

| Method | Path | 설명 | 인증 |
|--------|------|------|------|
| GET | /api/v1/members/me/recent-searches | 최근 검색어 목록(최신순) | JWT |
| DELETE | /api/v1/members/me/recent-searches/{id} | 검색어 개별 삭제 | JWT |
| DELETE | /api/v1/members/me/recent-searches | 검색어 전체 삭제 | JWT |

> 저장 엔드포인트는 없다 — `GET /places/search`가 인증 회원의 키워드를 자동 기록한다.

### 조회

```json
// GET /api/v1/members/me/recent-searches
// Response data
[
  { "id": 12, "keyword": "강남" },
  { "id": 9,  "keyword": "한강" }
]
```
- 최신순(`searched_at DESC`). 상한 개수 이내. 없으면 빈 배열.

### 개별 삭제

```
DELETE /api/v1/members/me/recent-searches/{id}
```
- 응답 데이터 없음(200). 본인 소유가 아니거나 없는 id면 삭제 없이 멱등 200(정보 노출 방지). *(또는 404 — 미해결 질문)*

### 전체 삭제

```
DELETE /api/v1/members/me/recent-searches
```
- 응답 데이터 없음(200). 회원의 모든 최근 검색어 제거(없어도 멱등 200).

## 완료 조건 (Acceptance Criteria)

- [ ] 로그인 회원이 검색하면 키워드가 저장되고, 같은 키워드 재검색은 중복 없이 최신으로 갱신(맨 앞)된다.
- [ ] 페이지네이션(cursor 있는) 재조회는 최근 검색어를 추가 기록하지 않는다.
- [ ] 비로그인 검색은 최근 검색어를 저장하지 않는다.
- [ ] 상한(15개) 초과 시 가장 오래된 검색어가 제거된다.
- [ ] 조회는 최신순으로 상한 이내를 반환한다.
- [ ] 개별 삭제는 본인 검색어만 지우고, 전체 삭제는 회원의 모든 검색어를 지운다(둘 다 멱등).
- [ ] 관련 테스트 통과 (`./gradlew test`).

## 미해결 질문

- **개별 삭제 시 없는/타인 id 응답** — 멱등 200 vs 404. (기본: 멱등 200, 정보 노출 방지)
