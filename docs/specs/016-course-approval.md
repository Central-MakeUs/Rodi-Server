## 배경 / 목적

사용자가 등록한 코스는 `PENDING`으로 쌓이고, 승인 전까지 전체 목록·검색에 나오지 않는다([014](014-course-registration.md)). 이걸 **승인·반려로 전환하는 관리자용 엔드포인트**가 필요하다.

**계정 권한(ROLE) 부여 작업이 아직 없다.** 그래서 이번에는 **로그인한 사용자면 누구나** 호출할 수 있게 열어두고, 권한 작업이 끝나면 관리자 전용으로 좁힌다.

> ⚠️ **임시 조치**: 지금 상태로는 **등록자가 자기 코스를 스스로 승인**할 수 있다. 운영 배포 전에 반드시 권한을 붙여야 하며, 스펙·Swagger·코드 주석에 임시임을 명시한다.

### 범위 밖

- **계정 권한(ROLE) 체계** — 별도 작업. 완료되면 이 엔드포인트에 권한 검사만 추가한다.
- **반려 사유 저장·노출** — 추후.
- **관리자 웹 화면·승인 대기 목록 조회 API** — 이번에는 상태 변경만.
- 승인/반려 알림(푸시·메일).

## 요구사항

### 기능 요구사항

1. **승인 상태 변경**: 코스의 승인 상태를 `PENDING`·`APPROVED`·`REJECTED` 중 하나로 바꾼다.
2. **즉시 반영**: `APPROVED`가 되면 그 순간부터 전체 목록·검색·연관검색어·마커·상세에 노출되고, `PENDING`·`REJECTED`로 바뀌면 즉시 빠진다.
3. **자유 전이·멱등**: 상태 전이에 제약을 두지 않는다(승인을 되돌릴 수 있어야 운영 실수를 고칠 수 있다). 같은 상태로의 변경은 아무 일도 하지 않고 200이다.

### 비기능 요구사항

- **인증**: JWT 필수. **인가는 임시로 없음**(로그인 사용자 전체) — 권한 작업 후 관리자 전용.
- 경로를 `/api/v1/admin/...` 아래 두어 일반 API와 섞이지 않게 한다. 권한이 생기면 이 prefix에 검사만 걸면 된다.

## API 명세 (패키지 `domain.place`)

| Method | Path | 설명 | 인증 |
|--------|------|------|------|
| PATCH | /api/v1/admin/courses/{courseId}/approval | 승인 상태 변경 | JWT (**임시**: 로그인 사용자 전체) |

**컨트롤러 배치**(CLAUDE.md 기준): 관리자 오퍼레이션은 사용자 API와 대상·권한이 달라 **`AdminCourseController` 전용**으로 분리한다. 단발 엔드포인트지만 앞으로 승인 대기 목록·반려 사유가 붙을 자리이고, 권한 검사를 컨트롤러 단위로 걸 수 있다.

**메서드**: 코스의 여러 속성 중 **승인 상태 하나만 바꾸는 부분 변경**이라 `PATCH`다.

### 승인 상태 변경

```json
// PATCH /api/v1/admin/courses/101/approval   (JWT)
// Request
{ "approvalStatus": "APPROVED" }

// Response data
{ "courseId": 101, "approvalStatus": "APPROVED", "approvedAt": "2026-08-11T14:02:11" }
```

- `approvalStatus`는 필수, `PENDING`·`APPROVED`·`REJECTED` 중 하나. 그 외 값은 400.
- **`APPROVED`로 바뀔 때만 `approved_at`을 현재 시각으로 갱신**한다. 다른 상태로 바뀌어도 지우지 않는다(마지막 승인 이력을 남긴다). 승인된 적 없으면 응답의 `approvedAt`은 `null`.
- **같은 상태로 보내면 멱등**이다 — 갱신 없이 현재 값을 그대로 반환한다(재승인으로 `approved_at`이 밀리지 않는다).
- 없는 `courseId`, 또는 주차장 `placeId`면 **404 `COURSE_404_1`**. **삭제된 코스**(`deleted_at IS NOT NULL`)는 **404 `COURSE_404_2`** — 지워진 코스를 승인해 되살릴 수 없다.
- **운영자 시딩 코스(`created_by_member_id IS NULL`)도 대상**이다 — 부적절한 코스를 내리는 데 쓸 수 있다.

### 에러 코드

[014](014-course-registration.md)의 `CourseErrorCode`를 그대로 쓴다. 신규 코드는 없다.

| 코드 | HTTP | 메시지 |
|------|------|--------|
| `COURSE_404_1` | 404 | 코스를 찾을 수 없습니다. |
| `COURSE_404_2` | 404 | 삭제된 코스입니다. |

권한 작업 후 추가 예정: `COURSE_403_2` (403, "관리자만 코스 승인 상태를 변경할 수 있습니다.")

## 완료 조건 (Acceptance Criteria)

- [ ] `PENDING` 코스를 `APPROVED`로 바꾸면 `approved_at`이 채워지고, **그 직후 전체 목록·검색·연관검색어·마커·상세에 노출된다**.
- [ ] `APPROVED` 코스를 `REJECTED`로 되돌리면 즉시 전체 조회에서 빠지고, 등록자의 내 코스 목록에는 `REJECTED`로 남는다([015](015-my-course-management.md)).
- [ ] 같은 상태로 다시 보내면 200이고 `approved_at`이 바뀌지 않는다.
- [ ] 정의되지 않은 상태 값은 400, 없는 코스·주차장 id는 404, 삭제된 코스는 `COURSE_404_2`다.
- [ ] 미인증 요청은 401이고, **인증된 요청은 등록자 본인이든 아니든 모두 성공한다**(임시 정책의 검증 — 권한 작업 시 이 항목을 뒤집는다).
- [ ] 관련 테스트 통과 (`./gradlew test`).
