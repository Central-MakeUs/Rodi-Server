## 배경 / 목적

등록한 코스는 관리자 승인 전까지 전체 목록·검색에 나오지 않는다([014](014-course-registration.md)). 그래서 사용자는 **자기가 낸 코스가 지금 어떤 상태인지 확인할 창구**가 필요하다. 승인 대기·승인·반려를 상태별로 볼 수 있게 하고, 잘못 등록한 코스는 지울 수 있게 한다.

**수정은 제공하지 않는다.** 승인 워크플로와 얽혀 규칙이 급증하고(승인된 코스를 고치면 재심사로 되돌릴지, 심사 중 수정을 허용할지, 좌표가 바뀌면 [011](011-practice-course.md)의 방문 인증 기준이 흔들리는 문제) 3차 범위에 비해 이득이 작다. 잘못 등록했으면 **삭제 후 재등록**한다.

### 범위 밖

- **코스 수정(PUT)** — 구현하지 않는다.
- **반려 사유 표시** — 상태만 보여준다(사유 저장은 추후).
- 코스 상세 진입 화면 — 목록 응답은 코스명·상태·생성일만 담는다.

## 요구사항

### 기능 요구사항

1. **내 코스 목록**: 내가 등록한 코스를 **최신 등록순**으로 커서 페이지네이션해 반환한다. 항목은 **코스명·승인 상태·생성 날짜**(+ 동작에 필요한 `courseId`).
2. **승인 상태별 조회**: `status` 파라미터로 `PENDING`·`APPROVED`·`REJECTED` 중 하나만 걸러 볼 수 있다. 없으면 전체.
3. **삭제**: 내가 등록한 코스는 **승인 상태와 무관하게** 삭제할 수 있다. 운영자 시딩 코스(`created_by_member_id IS NULL`)는 삭제할 수 없다.
4. **삭제된 코스 안내**: 이미 그 코스를 저장·연습 중이던 사용자에게는 **"삭제된 코스입니다"** 를 보여준다. 남의 북마크·후기·연습기록을 지우지 않는다.
5. **목록에서도 삭제를 표시**: 저장 목록·연습 목록의 항목에 삭제 여부를 함께 내려, 앱이 **탭하기 전에** 비활성/배지로 구분할 수 있게 한다.

### 비기능 요구사항

- 모든 엔드포인트 **JWT 필수**.
- 목록은 **커서 페이지네이션**(ADR 0010), 공통 `CursorPage<T>` 재사용. `totalCount`는 첫 페이지에서만.
- 삭제는 **soft delete**(`course.deleted_at`, V24 — [014](014-course-registration.md) 참고). 행을 지우지 않으므로 FK를 손대지 않는다.

## API 명세 (패키지 `domain.place`)

| Method | Path | 설명 | 인증 |
|--------|------|------|------|
| GET | /api/v1/members/me/courses | 내가 등록한 코스 목록(상태 필터·커서) | JWT |
| DELETE | /api/v1/courses/{courseId} | 내 코스 삭제(soft delete, 멱등) | JWT |

기존 API 확장: **저장 목록**(`GET /places/bookmarks`)·**연습 목록**(`GET /members/me/practices`) 응답에 `isDeleted` 추가(아래 3번).

**컨트롤러 배치**: 둘 다 [014](014-course-registration.md)에서 만든 `CourseController`에 둔다. 목록은 회원 소유라 `/members/me/courses`, 개별 조작은 대상 자체를 가리키는 `/courses/{courseId}` — [011](011-practice-course.md)의 `practices`와 같은 규칙이다.

### 1. 내 코스 목록

```
GET /api/v1/members/me/courses?status=PENDING&size=20&cursor=   (JWT)
```

| 파라미터 | 필수 | 설명 |
|----------|------|------|
| `status` | N | `PENDING`·`APPROVED`·`REJECTED`. 없으면 전체 |
| `size` | N | 기본 20, 1~100 (벗어나면 400) |
| `cursor` | N | 이전 페이지의 `nextCursor` |

```json
// Response data — CursorPage<MyCourseItem>
{
  "items": [
    { "courseId": 101, "name": "압구정 한강 코스", "approvalStatus": "PENDING", "createdAt": "2026-08-11T10:24:03" },
    { "courseId": 98,  "name": "양재천 코스",     "approvalStatus": "REJECTED", "createdAt": "2026-08-09T21:11:40" }
  ],
  "hasNext": false,
  "nextCursor": null,
  "totalCount": 2
}
```

- 정렬/커서: **최신 등록순** — `created_at DESC, place_id DESC`. 커서는 `(생성시각, id)` base64(`CursorCodec`).
- `totalCount`는 **첫 페이지에서만**, **필터가 적용된 개수**다(`status=PENDING`이면 승인 대기 건수).
- 내가 등록한 코스만 나온다(`created_by_member_id = 나 AND deleted_at IS NULL`). 운영자 시딩 코스·삭제한 코스는 포함되지 않는다.
- 화면에 쓰지 않는 값(좌표·연습유형·주행거리)은 담지 않는다.

### 2. 내 코스 삭제

```
DELETE /api/v1/courses/101   (JWT)
```

- 응답 데이터 없음(200). `course.deleted_at = now`로 **표시만 하고 행은 남긴다**.
- **승인 상태와 무관하게 삭제된다**(승인 대기·승인·반려 전부).
- 없는 `courseId`·이미 삭제된 코스는 **멱등 200**([011](011-practice-course.md) 삭제와 동일 규칙).
- 남의 코스·운영자 시딩 코스(`created_by_member_id IS NULL`)는 **403 `COURSE_403_1`**.
- 주차장 `placeId`를 보내면 404(코스가 아니다).

**왜 soft delete인가.** 승인된 코스에는 이미 남의 북마크·후기·연습기록이 붙어 있다. 물리 삭제하면 그것들이 조용히 함께 사라져, 저장해둔 사용자는 목록에서 항목이 없어진 이유를 알 수 없다. 행을 남기고 **"삭제된 코스입니다"** 를 띄우면 사라진 사실이 설명된다. FK cascade를 재정의할 필요도 없어져 마이그레이션도 가벼워진다.

**삭제 후 각 화면의 동작**

| 화면 | 결과 |
|------|------|
| 전체 목록·검색·연관검색어·마커 좌표 | **빠진다**(노출 필터에 `deleted_at IS NULL` — [014](014-course-registration.md)) |
| 내 코스 목록 | **빠진다**(등록자 본인 목록에서도 제외) |
| 코스 상세 | **404 `COURSE_404_2` "삭제된 코스입니다."** — 등록자 본인도 동일 |
| 남의 북마크 목록·연습 목록 | **항목이 남고 `isDeleted=true`가 붙는다**(아래 3번) |
| 이미 작성된 후기 | 그대로 남는다(코스 상세로만 노출되므로 사실상 보이지 않는다) |

- 북마크·연습 목록에서 **항목을 즉시 빼지 않는 이유**: 목록에서도 조용히 사라지면 "삭제된 코스입니다"를 보여줄 지점이 없어진다. 대신 목록 응답에 삭제 여부를 실어 앱이 탭하기 전에 구분하게 한다.
- **레벨 누적 거리는 차감되지 않는다** — [012](012-level-progress.md)의 확정 사항(연습기록을 지워도 누적은 그대로)이 그대로 적용된다.
- **복구 API는 두지 않는다.** `deleted_at`을 되돌리면 복구되지만 이번 범위에서 엔드포인트로 열지 않는다.

### 3. 목록 응답에 삭제 표시 (기존 API 확장)

이미 담아둔 사용자가 **탭하기 전에** 알 수 있도록, 삭제된 코스를 담고 있는 두 목록에 `isDeleted`를 추가한다.

| 대상 | DTO | 비고 |
|------|-----|------|
| 저장 목록 `GET /places/bookmarks` ([006](006-mypage.md)) | `PlaceListItem` | 공유 DTO라 뷰포트 목록·검색에도 필드가 생기지만 그쪽은 노출 필터 때문에 **항상 `false`**다. 주차장도 항상 `false` |
| 연습 목록 `GET /members/me/practices` ([011](011-practice-course.md)) | `PracticeItem` | |

```json
// 저장 목록 항목 (발췌)
{ "placeId": 101, "name": "압구정로데오역", "placeType": "COURSE", "isDeleted": true, "distance": 320.5 }
```

- 값은 `course.deleted_at IS NOT NULL`이다. 목록 쿼리에 `course` LEFT JOIN을 더해 항목별 추가 조회 없이 채운다.
- **저장한 장소 수(`savedPlaceCount`)는 그대로 센다** — 항목이 목록에 남아 있으므로 개수와 목록이 어긋나지 않는다.
- 앱은 이 값으로 항목을 비활성/배지 처리하고, 그래도 탭하면 상세에서 `COURSE_404_2`를 만난다(이중 안전장치).

### 에러 코드 (`CourseErrorCode` 추가)

| 코드 | HTTP | 메시지 |
|------|------|--------|
| `COURSE_403_1` | 403 | 본인이 등록한 코스만 삭제할 수 있습니다. |

## 완료 조건 (Acceptance Criteria)

- [ ] 내가 등록한 코스만 최신 등록순으로 반환되고, 남의 코스·운영자 시딩 코스는 포함되지 않는다.
- [ ] `status=PENDING|APPROVED|REJECTED`로 각각 걸러지고, 없으면 전체가 나온다.
- [ ] `size`만큼 끊어 `hasNext`·`nextCursor`로 이어진다(2페이지 연속성·중복 없음), `size`가 0이나 101이면 400이다.
- [ ] `totalCount`는 첫 페이지에서만 채워지고 **필터 적용 후 개수**다.
- [ ] 항목이 `courseId`·`name`·`approvalStatus`·`createdAt`만 담는다.
- [ ] 승인 대기·승인·반려 코스가 모두 삭제되고, `deleted_at`이 채워진다(행은 남는다).
- [ ] 삭제 후 그 코스가 내 코스 목록·전체 목록·검색·연관검색어·마커 좌표 어디에도 없다.
- [ ] 삭제된 코스의 상세는 등록자 본인에게도 **404 `COURSE_404_2`("삭제된 코스입니다.")** 다.
- [ ] 승인된 코스를 삭제해도 다른 사용자의 `bookmark`·`review`·`member_practice` 행이 **그대로 남는다**.
- [ ] 삭제된 코스를 담고 있던 사용자의 **저장 목록·연습 목록 항목에 `isDeleted=true`** 가 실리고, 살아 있는 코스·주차장은 `false`다.
- [ ] 뷰포트 목록·검색 응답의 `isDeleted`는 항상 `false`다(삭제된 코스가 애초에 나오지 않는다).
- [ ] 남의 코스·운영자 코스(`created_by IS NULL`) 삭제는 403, 없는 id·이미 삭제된 코스는 200(멱등), 주차장 id는 404다.
- [ ] 모든 엔드포인트가 미인증 시 401이다.
- [ ] 관련 테스트 통과 (`./gradlew test`).

## 확정된 결정

- **수정(PUT)은 구현하지 않는다** — 삭제 후 재등록.
- **삭제는 상태 무관 전면 허용 + soft delete** — 승인된 코스도 등록자가 지울 수 있고, 남의 북마크·후기·연습기록은 지우지 않는다.
- **삭제된 코스 상세는 `COURSE_404_2`("삭제된 코스입니다.")** 로 구분해 안내한다 — 사전 확인 다이얼로그를 서버가 강제하지 않는다.
- **운영자 시딩 코스는 사용자가 삭제할 수 없다**(`created_by_member_id IS NULL` → 403).
- **목록 응답은 코스명·상태·생성일만** — 화면에 쓰는 값만 담는다.
- **반려 사유는 이후 구현** — 이번엔 상태만 보여준다.
