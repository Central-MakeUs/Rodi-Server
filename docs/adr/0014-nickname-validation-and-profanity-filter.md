# ADR 0014: 닉네임 검증 — 형식 규칙 + 리소스 금칙어(포함/정확 일치 분리)

## 상태 (Status)

Accepted (2026-10-08)

## 배경

닉네임은 지금까지 가입 시 990개 후보 풀에서 **자동 부여만** 됐다([스펙 004](../specs/004-onboarding.md)). 이번에 사용자가 직접 닉네임을 바꿀 수 있게 하면서, 자유 입력을 막을 규칙이 필요해졌다.

- 길이: 2자 이상 10자 이하
- 중복 불가(영문 대소문자 무시)
- 욕설·비속어·운영자 사칭 차단

금칙어 목록을 고르면서 두 가지를 확인했다.

**① 출처가 불분명한 목록은 쓸 수 없다.** 처음 검토한 「다국어 언어 필터링.csv」(4,314개)는 게임 클라이언트에서 추출한 데이터가 섞인 것으로 알려져 있고, 배포처도 "출처 불분명·라이선스 확인 필요"로 표시하고 있다. 한국어 비속어 목록으로 흔히 소개되는 저장소들도 라이선스가 없는 경우가 많았다. 단어 목록이면서 라이선스가 명확한 것은 **LDNOOBW**(CC BY 4.0, 한국어 72개·영어 403개)뿐이었다.

**② 단순 "포함" 검사는 오탐이 심하다.** 위 CSV로 정상 단어를 시험해 본 결과다.

| 문제 | 예 |
|---|---|
| 한 글자 항목 | `년`·`놈`·`젖`·`엿` → 청년·소년·젖소·엿장수 차단 |
| 일상어 | `시간`·`관장`·`생리`·`어미`·`유모`·`미친` → 시간부자·관장님·어미새·유모차 차단 |
| 영문 부분 일치 | `ass`·`sex`·`cunt` → class·passenger·sussex 차단 |
| 비속어 포함 일상어 | `시발` → 시발점 차단 |

## 결정

### 1. 형식 규칙 — 공백 대신 `_`

- 앞뒤 공백을 제거한 뒤 검증한다.
- 길이는 **2~10자**, 사용자가 보는 글자 수(grapheme cluster) 기준이다([스펙 018](../specs/018-text-length-grapheme.md)과 같은 단위). `_`도 1자로 센다.
- 허용 문자는 **완성형 한글, 영문, 숫자, `_`** 이다. `_`는 처음·끝에 올 수 없고 연속(`__`)도 안 된다.
- **공백은 허용하지 않는다.** 서버가 공백을 `_`로 자동 변환하지 않고 거부한다. 서버가 값을 바꾸면 중복 확인 결과와 실제 저장값이 달라질 수 있기 때문이다. 필요하면 앱이 입력 단계에서 변환한다.
- 자모 단독(ㅋㅋ·ㅅㅂ), 이모지, 그 밖의 특수문자는 거부한다.
- 변경 횟수 제한은 두지 않는다.

**공백을 `_`로 바꾼 이유** — 공백은 앞뒤·연속·전각 공백·NBSP처럼 눈에 안 보이는 변형이 많아 검증 예외가 늘어난다. `_`로 바꾸면 닉네임이 한 덩어리가 되어 화면에서 경계가 분명하고, 이후 멘션·URL에 쓰기도 쉽다.

**기존 닉네임 이관** — 후보 풀("차근차근 토끼")은 모두 단어 사이 공백 1칸 형식이다(공백 1개 946개, 2개 44개, 연속 공백 없음). Flyway 마이그레이션으로 기존 `member.nickname`의 공백을 `_`로 바꾸고, 후보 풀 파일도 같은 형식으로 변환한다. 현재 `_`가 든 닉네임은 없으므로 변환해도 중복은 생기지 않는다.

### 2. 금칙어는 리소스 파일로 번들한다

닉네임 후보 풀과 같은 방식이다. 기동 시 메모리에 불변으로 로드하고, 별도 테이블은 두지 않는다.

**출처**

- **LDNOOBW**(한국어·영어, CC BY 4.0)를 기본으로 쓴다. 파일 상단에 저작권자(Shutterstock, Inc.)·원본 링크·라이선스·변경 사항을 적고, 파일 안에서 출처별로 구역을 나눈다.
- **직접 작성**한 항목을 더한다. 한국어 대표 비속어와 그 표기 변형, 그리고 Rodi 운영자 사칭 예약어(`운영자`·`관리자`·`admin`·`rodi`·`로디` 등)다.
- 출처·라이선스가 명확하지 않은 목록은 쓰지 않는다.

**판정 방식에 따라 세 파일로 나눈다**

| 파일 | 판정 | 담는 것 |
|---|---|---|
| 포함 금칙어 | 정규화한 닉네임에 **들어 있으면** 거부 | 어디에 붙어도 욕인 단어(`씨발`·`병신` 등) |
| 정확 일치 금칙어 | 정규화한 닉네임 **전체가 같으면** 거부 | 한 글자 항목, 일상어와 겹치는 항목(`미친`·`망가`·`유모`·`ass`·`sex` 등) |
| 허용 목록 | 포함 일치가 **이 단어 하나에 통째로 덮이면** 무시 | 포함 금칙어를 품은 정상 단어(`시발점` 등) |

### 3. 정규화한 뒤 비교한다

비교 전에 소문자로 바꾸고, **`_`·숫자·특수문자를 지운다**. `씨_발`·`시1발` 같은 끼워넣기 우회를 막기 위해서다. 금칙어 파일도 같은 규칙으로 정규화해 로드한다. 초성(`ㅅㅂ`)은 형식 규칙에서 이미 걸러진다.

### 4. 중복은 대소문자를 무시한다 — 서비스 검사 + DB 제약

`Drive_Kim`과 `drive_kim`은 같은 닉네임으로 본다. 대소문자만 바꿔 다른 회원을 사칭하는 것을 막기 위해서다.

- 서비스에서 먼저 대소문자를 무시하고 확인해 409로 응답한다.
- 동시 요청은 DB가 막는다. 기존 `uq_member_nickname`(대소문자 구분) 제약을 **`lower(nickname)` 유니크 인덱스**로 바꾼다. 기존 닉네임은 모두 한글이라 바꿔도 충돌이 없다.
- 본인의 현재 닉네임을 다시 제출하거나 대소문자만 바꾸는 것은 허용한다.

## 결과

### 긍정적

- 라이선스가 명확한 데이터만 레포에 들어간다.
- 대표적인 오탐(청년·시발점·class·유모차)을 피한다.
- 외부 API나 새 테이블 없이 기존 닉네임 풀과 같은 구조라 단순하다.
- 공백 관련 검증 예외가 사라진다.

### 부정적

- 공개 목록이 작아 직접 작성할 분량이 있고, 처음에는 미탐이 있을 수 있다. 발견될 때마다 보강한다.
- 금칙어를 바꾸려면 재배포가 필요하다. 운영 중 즉시 추가할 수 없다.
- 포함/정확 일치 분류와 허용 목록은 사람이 판단해야 한다.
- 정규화가 숫자를 지우므로, 정확 일치 금칙어에 숫자만 붙인 닉네임(예: `미친2`)도 거부된다. 드물다고 보고 받아들인다.
- **기존 닉네임이 바뀐다**("차근차근 토끼" → "차근차근_토끼"). 앱 표시가 달라지므로 앱 팀과 공유해야 한다.

### 중립적

- 기존 회원 닉네임은 금칙어로 소급 검사하지 않는다. 후보 풀 990개는 `_` 변환 후에도 형식 규칙을 모두 통과한다.
- CC BY 4.0은 출처 표시와 변경 사항 명시를 요구한다. 리소스 파일 상단 주석으로 충족한다.

## 검토한 대안

### 출처 불분명한 대형 목록 사용

「다국어 언어 필터링.csv」처럼 수천 개짜리 목록은 커버리지가 넓지만, 재배포 권리가 없다. 면책 문구를 달거나 기업명만 지우는 방식으로도 출처 문제는 해결되지 않아 택하지 않았다.

### 금칙어 전체를 "포함" 검사

구현이 가장 단순하지만, 위 표의 오탐 때문에 정상 닉네임이 대량으로 막힌다.

### 금칙어 전체를 "정확 일치" 검사

오탐은 없지만, "씨발운전"처럼 다른 글자를 붙이기만 하면 통과한다.

### 공백 유지 / 공백 없앰

공백을 유지하면 기존 닉네임은 그대로지만 공백 변형에 대한 검증 예외가 남는다. 공백을 아예 없애면("차근차근토끼") 단어 경계가 사라져 읽기 어렵다. `_`가 둘의 절충이다.

### 외부 필터링 API

닉네임 변경 한 건에 외부 호출·비용·장애 지점이 생겨 규모에 비해 과하다.

### DB 테이블로 금칙어 관리

재배포 없이 바꿀 수 있지만, 관리 화면이 없는 지금은 이점이 없다. 운영 중 수정 요구가 생기면 재검토한다.
